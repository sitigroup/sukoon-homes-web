Area Wise Plugin — Changelog

Product: Sukoon Homes — Area Listing (Area Wise)

Version: 2.0.0

Release date: 21 May 2026

Environments: admin-homes.sukoon.group · homes.sukoon.group

Summary

Version 2.0.0 completes the Area Wise location system for property and project listings: admin map/GPS workflows, agent permissions, customer admin controls, and frontend area filters. This release fixes map pin behaviour, prevents random area assignment on GPS, and adds server-side name matching when the map pin moves.

1. Admin Property & Project — Area Wise Location

1.1 Location fields

  • Area Wise Location block on property and project create/edit pages.
  • Fields: State, City (synced from main form), Area, Sub Area, manual customer address.
  • Hidden internal state_id / city_id selects (no Select2 on hidden fields).
  • Detected area/sub-area hidden fields for save when no DB match exists.
  • area_listing_admin_save=1 on admin forms for auto-create rules.
  • Get Current Location: browser GPS + Google reverse geocode (not raw coordinates for city/address).

1.2 Map integration (maps-helper.js)

  • Single backend map instance (initBackendPlacesMap).
  • Draggable marker; drag end calls server geocode API with Google client fallback.
  • City search via backend places list — not legacy Autocomplete on property pages.
  • Pin move updates address, city, state, country, latitude, longitude.
  • Pin move does not keep city suggestion dropdown open.
  • Advanced Marker: dragend and gmp-dragend supported.

1.3 Legacy map fix (custom.js)

  • initMap() defers to initBackendPlacesMap when backendPlacesMapOptions is set.
  • Fixes duplicate map, stuck city dropdown, and lat/lng-only updates on pin drag.

1.4 Script load order

  • initMap and backendPlacesMapOptions defined before Google Maps API script.
  • Cache-bust maps-helper.js after updates.

2.1 resolve-coordinates

  • Route: POST /area-listing/resolve-coordinates
  • Name-only match from Google location_components (no distance-based nearest area).
  • Returns area_id, sub_area_id, and detected names when matched in DB for city.

2.2 Pin move apply flow

  • Clears Select2 area/sub-area display when location changes.
  • Parses area name from formatted address when Google components omit sublocality.
  • Falls back to client dropdown name match if server returns no match.

9. Known Limitations

  • Area auto-select needs matching name in DB for that city, or staff pick/add once.
  • Separate “Client Address” field may not update from map pin.
  • Low GPS accuracy: warning shown; drag pin if city wrong.
